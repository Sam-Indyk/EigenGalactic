The Linear Algebra Behind Image Deblurring

At its core, blurring an image is a mathematical operation that can be described using linear algebra. Understanding this allows us to systematically attempt to reverse the process, which is known as deconvolution or deblurring.

1. Representing Images as Vectors

Computers see images as a grid of pixels, where each pixel has a numerical value for its brightness. To use linear algebra, we "unroll" this grid into a single, very long column vector. Each element of the vector corresponds to a single pixel's value. For a color image, we would have separate vectors for the Red, Green, and Blue channels.

For example, a simple 3x3 grayscale image can be transformed like this:

$$ \begin{bmatrix} 10 & 20 & 30 \\ 40 & 50 & 60 \\ 70 & 80 & 90 \end{bmatrix} \quad \longrightarrow \quad \mathbf{x} = \begin{bmatrix} 10 \\ 20 \\ 30 \\ 40 \\ 50 \\ 60 \\ 70 \\ 80 \\ 90 \end{bmatrix} $$

2. The Blur as a Matrix Transformation

A blur is a type of **convolution**. This means each pixel's new value is a weighted average of itself and its neighbors. The set of weights is called the **kernel** (or Point Spread Function, PSF). For example, a simple motion blur kernel might average pixels along a line.

Crucially, the entire convolution operation can be represented by a single, large transformation matrix, which we can call $H$. When this matrix multiplies our image vector $\mathbf{x}$, the result is a new vector $\mathbf{b}$ representing the blurred image.

$$\mathbf{b} = H \mathbf{x}$$

Each row in the matrix $H$ is constructed to calculate the value for one specific pixel in the output. It contains the kernel's weights, shifted to the correct positions.

3. Deblurring: The Richardson-Lucy Algorithm

Since blurring is just $\mathbf{b} = H \mathbf{x}$, it seems like we should be able to deblur by calculating $\mathbf{x} = H^{-1}\mathbf{b}$. However, as explained below, the matrix $H$ is ill-conditioned, and its inverse is unstable and amplifies noise. We need a more clever, iterative approach.

The **Richardson-Lucy algorithm** is a widely used iterative method based on Bayes' theorem. It doesn't try to find a perfect inverse, but instead tries to find the most probable original image $\mathbf{x}$ that would have resulted in the blurry image $\mathbf{b}$ we observe.

The Iterative Formula:

The algorithm starts with an initial guess for the sharp image (often, the blurry image itself) and refines it over several iterations. The update rule for each iteration $(k+1)$ is:

$$ \mathbf{x}^{(k+1)} = \mathbf{x}^{(k)} \odot \left( H^T * \frac{\mathbf{b}}{H * \mathbf{x}^{(k)}} \right) $$

Breaking it Down:

  1. $H * \mathbf{x}^{(k)}$: **Re-blur the current estimate.** We take our current guess for the sharp image ($\mathbf{x}^{(k)}$) and apply the known blur matrix $H$ to it.
  2. $\frac{\mathbf{b}}{...}$: **Calculate the error ratio.** We compare the observed blurry image ($\mathbf{b}$) to our re-blurred estimate. If our estimate is good, this ratio will be close to a matrix of all 1s. Where it's different, it indicates an error.
  3. $H^T * ...$: **Apply the "correction."** We correlate the error ratio with the transpose of the blur matrix, $H^T$. This step effectively spreads the correction factor back across the image in a way that reverses the original blur.
  4. $\mathbf{x}^{(k)} \odot ...$: **Update the estimate.** We multiply our previous estimate by the correction factor (element-wise multiplication, $\odot$) to get our new, improved estimate for the sharp image, $\mathbf{x}^{(k+1)}$.

By repeating this process, the estimate $\mathbf{x}$ gets closer and closer to the true, sharp image.

4. Reconstruction: Prior Knowledge in Action

After deconvolution, we have a grayscale image that is sharper but may have soft edges or artifacts. To get a perfect, scannable QR code or clean pixel art, we must enforce our "prior knowledge" about the image's structure. This is done through a process of downsampling and thresholding.

The Linear Algebra of Averaging

Your intuition was correct: we are essentially looking at the average color within each block (or "module"). This averaging operation is a linear transformation. We can think of it as a **dot product**.

If we have a module of $N$ pixels from the deconvolved image, represented by a vector $\mathbf{v}_{module}$, we can find its average brightness by taking the dot product with a special vector, $\mathbf{m}_{avg}$:

$$ \text{Average} = \mathbf{m}_{avg} \cdot \mathbf{v}_{module} \quad \text{where} \quad \mathbf{m}_{avg} = \begin{bmatrix} 1/N \\ 1/N \\ \vdots \\ 1/N \end{bmatrix} $$

This linear operation projects the high-dimensional pixel data from the module down to a single scalar value representing its average brightness. For color pixel art, this is done independently for the Red, Green, and Blue channels.

The Non-Linear Decision

The final step is to decide the final color of that module. For QR codes, this is a **thresholding** operation, which is a simple but critical **non-linear** function:

$$ \text{Final Module Value} = \begin{cases} \text{White} & \text{if Average} > \text{Threshold} \\ \text{Black} & \text{if Average} \leq \text{Threshold} \end{cases} $$

For color pixel art, we simply use the calculated average color as the final color for the entire block. By applying this process, we convert the fuzzy, grayscale deconvolved image into a clean, blocky, and correct final image.
